# Writing about this project

Start with what a person can do with the product. Explain it in familiar words
before describing the implementation.

- Keep the opening to a short promise and one or two concrete sentences.
- Show a real workflow. Prefer the actual interface and clearly label sample data.
- Describe three to five useful capabilities, each with a specific user benefit.
- State the current status accurately: experiment, prototype, or working release.
- Put setup prerequisites before commands. Keep commands tied to the checked-in code.
- Link deeper technical material from a short README instead of removing it.
- Use simple black-and-white visuals with readable type and enough space.
- Avoid unmeasured performance claims, invented adoption, superlatives, and AI buzzwords.
- Keep privacy and product limits where they help someone decide whether to use it.
- Recheck links and screenshots when features or commands change.

The README is the product’s introduction. The linked guides are the technical
reference. Neither changes the repository’s operating or authorization rules.
